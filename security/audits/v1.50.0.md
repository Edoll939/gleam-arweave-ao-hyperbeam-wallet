# Gleam v1.50.0 security audit

## Scope

Diff: `cb7e37c..013e710`. The release fixes the community-scan reports filed against v1.49.x, adds a page history and the page's path to the dApp browser, loads collectible media from `/raw/`, and names the signed `.crx` again at the end of `release-app.sh`.

Surface paths changed, by theme:

- **Approvals.** `approval.ts` pins the wallet a request signs or sends from (`signingWallet`, from the entry's `walletId`) on the request it hands the window; `ApprovalRoot.tsx` shows that wallet as From, unlocks it and assesses the recipient against it, rather than the wallet active when the window loads (GHSA-v4px-wqq2-5j3p). Connect and addToken carry none. An approval's record is marked `attempted` in its own write before its work runs, and a record still marked after a worker restart is refused rather than run again, since the first run may already have posted. `tag-tiers.ts` headlines no `Type` other than `Message` that appears twice. `provider.ts` reads an L1 token transfer that also carries the activation winston as the transfer, and adds that winston to the fee shown; the reward signed is unchanged. `prepared-check.ts` keeps a leading byte order mark in the device step's text (`ignoreBOM`), as the approval screen does.
- **Request size.** `provider-params.ts` counts a site's transaction or data items (data, tags, each tag and item) as it reads them and refuses past 2 MiB, before the background decodes, hashes and stores the request.
- **Keys.** `key-session.ts` drops a key from the keyring when writing its session entry fails, so a wallet that reads as locked can't still sign.
- **Activity and tokens.** A merged activity entry keeps the type, counterparty, amount and token the wallet recorded for its own send; the gateway settles only status and timestamp. Token details come only from the process's own spawn transaction (`token-metadata.ts`). A collectible receipt keeps its `unverified` mark (`reads.ts`).
- **dApp browser.** The native views report the page's `<title>` with each navigation. `browser-sites.ts` keeps up to 300 visits (`local:browserHistory`) on this device: never backed up, cleared with the recent sites and on reset (`wallet-lifecycle.ts`), each read through `isValidBrowserVisit`. Titles lose control and format characters and are capped at 200 characters; URLs over 2048 characters aren't kept. The address bar shows the path after the host, with ID-like segments as `…` and control and format characters removed (`address.ts`); the host never shrinks. A page counts as visited only after it has loaded and stayed 1.5 s, so a shortener isn't recorded.
- **Build and release.** `surface.txt` and `CODEOWNERS` list the Android Gradle wrapper (`gradlew`, `gradlew.bat`, `gradle-wrapper.jar`). `release-app.sh` prints the path of `<tag>.crx` at the end when `pack-release.sh` left one in the repo root; it reads no credential. The version files carry 1.50.0.

Outside the surface: collectible media URLs and the gallery skeleton, the history screen, the threat model's note that a site's connection follows the active wallet.

Run: `pnpm vitest run`, tsc on all twelve projects, eslint, `pnpm deps:check`, `pnpm wxt:build`, `pnpm check:bundles`, `pnpm mobile:build`, `pnpm test:smoke`.

## Notes

F-2 is accepted: the read is bounded at three times the limit, and the stored-size cap (`PENDING_BYTES_PER_ORIGIN`) still refuses the request before it is held.

F-3 is accepted: the host comes first, never shrinks, and the path follows in muted text after `›`, so it doesn't read as the host.

F-4 is accepted: the URL loads only through `<img>` and `<video>`, which run no script, so the origin it is served from grants the media nothing.

Known limitations: no change.
