# Gleam v1.49.0 security audit

## Scope

Diff: `fe951c6..503424c`. The release fixes the community-scan reports filed against v1.48.0, marks your own wallets in the recipient suggestions, and changes the scan program's rules: only Medium and above is paid, severity comes from a three-question rubric, and `pnpm scan finish` checks advisory drafts.

Surface paths changed, by theme:

- **Concurrent storage writes.** `wallet-lifecycle.ts` renames a wallet, confirms a backup and saves upgraded envelopes under `withSessionLock`; the envelope upgrade the unlock starts queues behind the unlock rather than waiting on itself. `backup.ts` checks the vault is empty again under that lock before a restore writes, and merges pulled wallets under it only while the vault still uses the backup id the write started with, so a reset or a new setup during a write is left alone. A write reads the file back and writes again, at most 3 times, when another install's write replaced its copy.
- **Backup key cost.** `backup.ts` reuses a stored envelope's Argon2id salt and cost for the backup key only when that envelope is at the current default (`envelopeNeedsUpgrade`); otherwise it wraps at `DEFAULT_ARGON2ID_PARAMS`.
- **Approvals.** `findPending` (`approval.ts`) treats a record that carries an outcome as settled, like `findLive`, so it can't be read or resolved twice. A token whose ticker or name copies a registered token's, from a process that isn't that token, is flagged `tokenImpersonating` (`create-runtime.ts`, `provider.ts`); the transfer review shows the full process id, a warning, and holds the approve button like an unknown scale (`model.ts`, `TransferReview.tsx`). `addWatchedToken` refuses such a token (`reads.ts`). `impersonation.ts` folds U+051D onto `w`. The batch lookalike warning diffs the known address against the recipient it was flagged for (`assess.ts`). An AR transfer card shows the size of the data it carries. `tag-tiers.ts` headlines no `Action` that appears twice, and puts no `Quantity` that appears twice beside the headline. `UntrustedText.tsx` marks every space separator but the ordinary space, and the blank Braille pattern. Signed text keeps a leading byte order mark (`ignoreBOM`).
- **Keys.** `jwk.ts` refuses an imported key unless its modulus is exactly 4096 bits and its exponent is 65537. `Import.tsx` asks the platform to block screenshots while a keyfile is pasted. Keystone connect shows the full address and asks the user to check it on the device.
- **Peers and fetch caps.** `peer-discovery.ts` reads a probe answer at most 4096 bytes, refusing a larger `Content-Length` unread and cancelling a longer stream. `peers.ts` leaves peers the user removed or turned off out of L1 token reads. The iOS page-icon fetch (`PageIcon.swift`) streams and stops at its byte limit.
- **Build and release.** `well-known.mjs` compares the served `.well-known` files with the repo copies. `surface.txt` and `CODEOWNERS` list more build and test controls. `osv-scanner.toml` drops the withdrawn deepmerge ignore and records picomatch as dev-only. `scan/attestation.ts` rewords one error.

Outside the surface: the scan CLI's draft checks, the Points API's dock, floor and best-finding bonus (migration `014_scan_dock.sql`), the Points screen's bonus labels, the recipient suggestions, the scan docs and the site.

Run: `pnpm vitest run`, tsc on all twelve projects, eslint, `pnpm deps:check`, `pnpm wxt:build`, `pnpm check:bundles`, `pnpm mobile:build`, `pnpm test:smoke`.

## Notes

F-1 is accepted: the fallback keeps the list from ever being empty, and the shipped nodes are public reads with CORS `*` that the host permissions already allow. A read changes only the displayed balance.

F-2 is accepted: the limit only bounds memory, and an icon that size falls back to the next candidate URL.

F-3 is accepted: the check runs only on import. Arweave keys are RSA-4096 with exponent 65537, so a real key always passes.

Known limitations: no change.
